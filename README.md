# АЗС Simulator — прототип v0.1.1

Изометрическая игра на React, TypeScript, PixiJS и Capacitor. Основная цель сейчас — Android-приложение для POCO X6 5G с горизонтальным экраном. Игровые файлы входят в APK; сеть нужна только для проверки обновлений.

## Уже работает

- Полноэкранная изометрическая карта АЗС с дорогой, зданием и двумя колонками; фон создан по игровому концепту.
- Автомобили движутся по дороге в зависимости от времени суток, некоторые заезжают к колонкам и уезжают. Пока это визуальная симуляция без продажи топлива.
- Пауза, скорости 1×/2×/5×/10× и фиксированный шаг симуляции.
- Смена освещения и модель трафика по времени суток.
- Передвижение карты одним пальцем, масштабирование двумя пальцами (1×–3,5×).
- Верхняя панель с балансом, временем, трафиком и остатками топлива в раскрывающемся списке; меню с выходом из Android-приложения.
- Проверка нового APK в GitHub Releases при запуске Android-приложения, если оно собрано из GitHub Actions.

Экономика, обслуживание автомобилей, доставка и сохранения относятся к следующим этапам.

## Разработка

```bash
npm ci
npm run typecheck
npm test
npm run android:sync
```

`npm run dev` запускает локальную браузерную версию. Команда `npm run android:sync` собирает игру и копирует ресурсы в `android/`. Для локальной сборки APK нужен Android SDK API 36 и Java 21; после их установки выполните `npm run android:apk:debug`.

## Сборка APK на GitHub

В проекте есть два workflow:

- `.github/workflows/android-ci.yml` — на ветке `main` и по ручному запуску собирает отладочный APK как артефакт Actions.
- `.github/workflows/android-release.yml` — по тегу `v<version>` собирает подписанный APK и публикует GitHub Release.

Для обновлений из приложения репозиторий и Release должны быть **публичными**: приложение использует публичный GitHub API без встроенного токена. При сборке workflow передаёт имя репозитория в игру автоматически.

### Один раз: ключ подписи

Создайте ключ и храните его вне репозитория. Например:

```bash
keytool -genkeypair -v -keystore azs-release.jks -alias azs -keyalg RSA -keysize 3072 -validity 10000
base64 -w0 azs-release.jks
```

В настройках GitHub-репозитория добавьте Actions secrets:

| Secret | Значение |
| --- | --- |
| `AZS_KEYSTORE_BASE64` | Вывод команды `base64` для файла ключа |
| `AZS_STORE_PASSWORD` | Пароль хранилища |
| `AZS_KEY_ALIAS` | Алиас, например `azs` |
| `AZS_KEY_PASSWORD` | Пароль ключа |

Храните исходный `.jks` и пароли: все будущие обновления должны быть подписаны тем же ключом. Локальная папка `signing/` и файлы `.jks` исключены из Git. Если ключ создан в этой рабочей копии, сохраните резервную копию папки `signing/` вне проекта.

### Выпуск версии

1. Обновите `version` в `package.json`, `versionName` и увеличьте `versionCode` в `android/app/build.gradle`.
2. Отправьте изменения в `main`, затем создайте и отправьте тег с той же версией, например `v0.1.0`.
3. Дождитесь workflow **Android release** и скачайте APK со страницы GitHub Releases.
4. Установите APK на телефоне. Если ранее установлен отладочный APK, сначала удалите его: отладочный ключ отличается от релизного.

При запуске приложение проверяет последний опубликованный Release. Если версия новее и содержит APK, появляется кнопка скачивания. После загрузки нужно подтвердить установку в Android. Это сохраняет локальные данные при условии одинакового `applicationId`, ключа подписи и возрастающего `versionCode`.

## Структура

- `src/game/domain` — модель станции и ограничения.
- `src/game/simulation` — игровые часы и время суток.
- `src/ui/scene` — PixiJS-сцена и камера.
- `src/platform` — проверка GitHub Releases.
- `android/` — проект Capacitor для Android.
