# AZS Simulator v0.8.0 — Sound Update: техническое задание

## Цель
Внедрить звуковую подсистему в текущую игру без изменения механик, экономики, интерфейсов и сохранений, кроме явно описанных настроек звука. Приоритет: Android F2P. Версия 0.8.0.

## Состав переданных ресурсов
- `audio/sfx/*.wav`: 11 программно синтезированных прототипов. Это НЕ реалистичные записи; применять как временные эффекты с возможностью замены.
- `audio/music/*.ogg`: три ОРИГИНАЛЬНЫХ 32-секундных демонстрационных синтезированных лупа. Это технические заглушки, НЕ финальные профессиональные композиции продолжительностью 2–4 минуты. Не заявлять их как финальные треки.
- `docs/audio_manifest.json`: события, имена файлов, доступность.

## Музыка
- Стиль Lo-fi / Chill, инструментальная, без вокала. Финальная цель: три качественных бесшовных трека 2–4 мин каждый (требуют отдельного производства/лицензирования).
- 06:00–17:59 Morning Fuel; 18:00–21:59 Golden Hour Station; 22:00–05:59 Midnight Pump.
- Выбор по **игровому** времени; переход с кроссфейдом 2–4 секунды реального времени. Не запускать новые плееры на каждом тике.
- Сохранить нормальную высоту и темп музыки при 1×/2×/4×; не сбрасывать музыку при открытии окон или смене сцены.
- При паузе симуляции музыка может продолжаться, если приложение на переднем плане. При сворачивании/потере audio focus соблюдать политику платформы, останавливать/приглушать и восстанавливать корректно.
- Зацикливание без слышимых щелчков. Для демонстрационных файлов возможны небольшие музыкальные швы, устранить в финальных ассетах.

## Звуковые шины и настройки
- `musicVolume` 35%, `effectsVolume` 65%, `ambientVolume` 45% по умолчанию; 0–100%, mute при 0.
- Разделение на Music / UI+SFX / Environment. Автоматическое сохранение настроек в существующем механизме настроек, безопасные значения по умолчанию для старых сейвов.
- При открытии модальных окон уменьшать музыку примерно на 15–20% (опционально, не складывать снижение при вложенных окнах).
- Не создавать звуковые объекты в игровом цикле без необходимости. Предзагрузка/пул голосов; ошибки загрузки не должны ломать игру.

## События и маппинг
- UI: ui_click — кнопки (не при каждом изменении цен без нужды); ui_confirm — подтверждение; ui_error — ошибка; ui_purchase — покупка оборудования; ui_notification — доставка/уведомление; ui_warning — поломка/предупреждение; cash_register — завершённая покупка в магазине/кафе.
- ТРК: pump_nozzle_pickup — начало операции; pump_complete — завершение; pump_nozzle_return — возврат; цикл pump_fueling — пока идёт отпуск топлива (ФАЙЛ ОТСУТСТВУЕТ).
- Ремонт: repair_complete — успешное завершение; repair_tools — работа мастера (ФАЙЛ ОТСУТСТВУЕТ).
- Транспорт: vehicle_start, vehicle_idle, vehicle_pass, vehicle_stop (ФАЙЛЫ ОТСУТСТВУЮТ).
- Поставки: truck_arrival, truck_brake, fuel_unloading, goods_unloading (ФАЙЛЫ ОТСУТСТВУЮТ).
- Окружение: store_door, cafe_door, ambient_station (ФАЙЛЫ ОТСУТСТВУЮТ).
- Не подменять отсутствующие реалистичные звуки неподходящими эффектами. При отсутствии файла использовать тихий fallback/без звука и выводить dev-warning однократно.

## Приоритеты, лимиты и поведение
- UI-сигналы не теряются из-за звуков транспорта; 3–4 одновременных автомобильных голоса максимум; ограничить частоту повторов UI-кликов и кассы.
- Пространственное затухание по расстоянию до камеры, если движок поддерживает; иначе уровни по видимости/масштабу камеры. Отдалённые ТРК тише, музыка не зависит от камеры.
- Для многократных операций запускать звук на переходе состояния, а не на каждом кадре. Защита от дублирования при восстановлении сохранения, переключении скорости и открытии экранов.
- Во время 2×/4× не менять pitch; циклические звуки синхронизировать с логическим состоянием, а не растягивать механически.
- Для ремонта мастеров учитывать утверждённую систему v0.7.6: дешёвый/медленный, стандартный, дорогой/быстрый. Не возвращать найм/обучение/увольнение техников.

## Техническая интеграция
1. Изучить репозиторий, текущую ветку и реальный стек проекта, адаптировать архитектуру к нему. Не предполагать Unity/Godot/WebAudio заранее.
2. Создать единый AudioManager/сервис с API `play(event, context?)`, `startLoop(event, entityId)`, `stopLoop(event, entityId)`, `setVolume(bus, value)`, `setGameTime(time)`, `dispose()` или эквивалентом стека.
3. Привязать к существующим событиям/состояниям игры; не внедрять аудио через постоянный polling DOM и не дублировать обработчики.
4. Для браузерного аудио предусмотреть autoplay restrictions: активация после первого пользовательского действия. Для Android учитывать lifecycle/audio focus.
5. Добавить регуляторы в существующий экран «Настройки» в утверждённом визуальном стиле тёмного неона с зелёными акцентами.
6. Сохранить старые сейвы, бухгалтерию, расчёты цен, поставки, ремонт и UI без регрессий.
7. Проверить лицензии всех добавляемых извне ресурсов: допустимость коммерческого использования и распространения с игрой, требования атрибуции; записать авторов/URL/лицензии в `AUDIO_LICENSES.md`. Прототипы и демо-лупы из данного пакета сгенерированы программно, без сторонних семплов.
8. Не скачивать ассеты с непроверенной лицензией и не включать сторонние файлы без подтверждения условий.

## Критерии приёмки
- При запуске после первого взаимодействия слышна соответствующая игровому времени тема, бесконечно повторяется.
- Переключение 17:59→18:00, 21:59→22:00, 05:59→06:00 происходит плавно, без параллельного наложения нескольких треков после перехода.
- 0% любой шины полностью отключает её, изменения слышны сразу, после перезапуска настройки сохраняются.
- Все 11 доступных SFX корректно срабатывают только на соответствующих событиях; отсутствующие файлы не вызывают ошибок/крашей.
- Массовое движение транспорта, 8 ТРК, 10 парковочных мест, быстрый ход времени, многократное открытие настроек не вызывают аудиоспама, утечек и деградации FPS.
- Пауза, background/foreground, закрытие/открытие приложения, старые сохранения работают корректно.
- Успешные локальные сборка/тесты, документированный список проверок; не заявлять Android APK протестированным, если он не запускался на устройстве/эмуляторе.
- Изменения закоммичены и отправлены в GitHub, если доступна авторизация; если нет, сохранить локальный коммит и дать точные команды публикации, не заявлять push успешным.

## Границы релиза
Обязательное: работающая аудиосистема, 3 демо-лупа, 11 эффектов, настройки, события, тесты. Необязательное: финальная студийная музыка и отсутствующие реалистичные SFX; их отсутствие явно указать в release notes, не выдавать заглушки за полноценный набор.
