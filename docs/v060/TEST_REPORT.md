# AZS Simulator 0.6.0 — отчёт о проверке

Дата: 14.11.2026.

## Автоматические проверки

- `npm run typecheck` — пройдено.
- `npm test` — 113 тестов, 21 файл; регрессия старых версий и тесты 0.6 пройдены.
- `npm run build` — production web bundle собран.
- Новые тесты проверяют износ ТРК и резервуара, распределение литров, замедление заправки, миграцию 0.5.2, точную сохранность состояния, найм и обучение, зарплату на границе суток, однократную оплату штатного ремонта и подрядчика, отказ при нехватке денег, отмену и cooldown, приоритет автоматических задач, параллельных подрядчиков и движение подрядчика при трафике. Отдельно проверен жизненный цикл Wake Lock.

## Проверка интерфейса

Headless Chromium, 390×844 и 1280×720: главная сцена и техслужба открылись без ошибок JavaScript; на мобильном размере нет горизонтальной прокрутки; найм через UI работает. Полноэкранный раздел удерживает игровые часы на паузе. Сохранение с назначенным ремонтом восстановилось; статус ремонта и сотрудник отображаются на карте. Снимки: [мобильная техслужба](mobile-technical.png), [мобильная сцена](mobile-repair.png), [настольная сцена](desktop-repair.png).

## Android и устройство

`npm run android:apk:debug` успешно собрал web bundle и синхронизировал Capacitor, но Gradle не смог собрать APK: в локальной среде нет Android SDK (`SDK location not found`). Версия Android поднята до `versionCode 18` / `versionName 0.6.0`. Workflow релиза устанавливает SDK API 36 и собирает подписанный APK при публикации тега. Физическое Android-устройство и реальное удержание экрана ОС в этой среде не проверялись; покрыты тестом API и проверкой браузерного интерфейса.

## Известные ограничения проверки

- Снимки сделаны в эмуляции viewport браузера; это не тест на физическом телефоне.
- Проверка параллельных подрядчиков и отсутствия длительных заторов детерминирована; поведение при всех возможных комбинациях большой станции не доказано.
- Vite предупреждает о крупном основном JS chunk; сборка завершается успешно.

## Ручная проверка после установки

1. Открыть старое сохранение 0.5.2 и сверить деньги, оборудование, литры и заказы. Убедиться, что резервная копия создана один раз.
2. Построить ТРК и резервуар, дождаться фактической продажи и поставки; проверить снижение состояния и ускорение/паузу на 1×, 2×, 4×.
3. Нанять техника, назначить ремонт занятой ТРК, проверить ожидание, однократную оплату и возобновление после перезапуска.
4. Проверить подрядчика, обучение, увольнение, бухгалтерию и фильтры журнала.
5. На устройстве проверить Wake Lock при видимой игре, паузе, сворачивании и возвращении.
