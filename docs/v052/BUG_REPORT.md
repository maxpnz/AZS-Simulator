### Данные, нужные для закрытия B14 и точной проверки B11/B13/B18

Контрольный детерминированный прогон воспроизводится командой `node scripts/v052-traffic-diagnostics.mjs`; полная запись — [traffic-diagnostics.json](traffic-diagnostics.json). Для B11 прибытие бензовоза с `phaseSeconds=0/300/600` даёт последовательные позы служебной дороги и разворот к площадке. Для B13 зафиксирован `compact-crossover` ID 1: `leaving`, `(299.95, 680.85)`, heading `2.8616`, routeIndex `4`, target `exit`, `serviceRemainingSeconds=4`; он далее следует к левому выезду. Для B14 зафиксирован похожий диагональный проход у ТРК 2: `budget-sedan` ID 27, `toPump`, `(849, 796.8)`, heading `3.8416`, target `pump_2_approach`, таймер обслуживания `0`; к `gameSeconds=29820` он уже `leaving`, к `30870` удалён со сцены, диагностика заторов пуста. Для B18 контрольный ожидающий ID 31 имеет `status=queued`, `(681,755)`, heading `3.9816`, `pumpId=pump-1`, `waitedSeconds=0`; счётчик UI учитывает этот статус, но исключает `toPump` и `leaving`.

Сохранение 0.5.1, сделанное в момент проблемного кадра или сразу перед ним. Для каждой затронутой машины нужны `id, modelId, status, x, y, angle, route, routeIndex, pumpId, speed, waitedSeconds, serviceRemainingSeconds, phaseRemainingSeconds`; для бензовоза — `status, phaseSeconds, remainingMl`. Без этих полей классификация движения и обслуживания по снимку остаётся гипотезой.

Тестовый браузерный снимок использует изолированное сохранение с 5 ТРК и всеми шестью видами топлива; он не подменяет пользовательское сохранение. Декодированный объём новых 17 текстур — 15,14 МиБ против примерно 24 МиБ четырёх прежних автомобильных текстур; FPS и фактический расход GPU на физическом Android-устройстве пока не измерены. `cap sync android` прошёл, но `assembleDebug` остановился до компиляции: в локальной среде нет Android SDK (`ANDROID_HOME` или `sdk.dir`). Релизный APK собирается GitHub Actions с установленным Android SDK.

Прогоны симуляции покрывают 2, 5 и 10 ТРК, включая плотный трафик и бензовоз. В игре предусмотрены скорости 1×, 2×, 5× и 10×; отдельного режима 4× в 0.5.1 нет, поэтому он не добавлялся ради графического обновления.
